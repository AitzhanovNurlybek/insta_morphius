# Что дальше по проекту

Порядок важнее объёма: каждый следующий этап опирается на данные, которых
до предыдущего просто нет.

---

## Этап 0. Запустить то, что уже собрано (эта неделя)

Код есть, вживую он не проверялся. Пока этого не сделано, остальное считать
планами, а не задачами.

1. Завести проект в Supabase, выполнить `0001`, `0002`, `0003`, при желании `seed.sql`.
2. Заполнить `.env.local`, поднять `npm run dev`.
3. Назначить себя админом (SQL в [SETUP.md](SETUP.md)).
4. **Пройти сценарий целиком:** регистрация бизнеса → бриф → подбор creators →
   все статусы до «Завершена» → отчёт виден клиенту. Всё, что сломается, чинить сразу.
5. Задеплоить на Vercel и проверить то же самое на боевом домене.

Признак, что этап закрыт: агентство может провести настоящую кампанию,
не открывая таблицу.

## Этап 1. Наполнить и обкатать (2–4 недели)

1. **10–15 реальных креаторов** через `scripts/import-creators.mjs` или руками.
2. Провести 2–3 настоящие кампании внутри платформы, а не параллельно с ней.
3. Смотреть, где команда возвращается в WhatsApp и таблицы — это и есть список
   недостающих функций. Не угадывать заранее.
4. Параллельно: подать документы на **Business Verification** в Meta
   (идёт неделями, начинать надо сейчас) — [META_APP_REVIEW.md](META_APP_REVIEW.md).

## Этап 2. Убрать ручную рутину (1–2 месяца)

Что почти наверняка вылезет на этапе 1 — приоритет по факту, а не по списку:

- **Уведомления.** Новая заявка → сообщение агентству; смена статуса → сообщение
  клиенту. Первым делом Telegram-бот агентству (дёшево и мгновенно), затем
  WhatsApp клиенту.
- **Кабинет креатора.** Сейчас задачи передаются вручную. Как только креаторов
  станет больше десяти, отдельный вход с его задачами, дедлайнами и гонорарами
  сэкономит больше времени, чем что-либо ещё.
- **Шаблоны брифов** под типовые задачи (открытие точки, распродажа, новинка).
- **Экспорт отчёта в PDF** одной кнопкой вместо ручной вёрстки.

## Этап 3. Подключить Instagram официально (после одобрения Meta)

1. Включить переменные окружения, разослать креаторам персональные ссылки.
2. **Фоновое обновление метрик и продление токена.** Токен живёт 60 дней;
   в текущем коде метрики тянутся один раз, в момент подключения. Нужен
   cron (Vercel Cron или задача в Supabase) раз в сутки: обновить метрики,
   продлить токен, обновить `instagram_last_synced_at`.
3. Бейдж «✅ Подтверждено через Instagram» зажигается сам по `data_source`.

## Этап 4. Creator Score и подбор (когда накопятся данные)

Раньше, чем через 20–30 завершённых кампаний, формула будет выдуманной.
К этому моменту в базе уже лежит нужное сырьё: оценки по четырём осям,
история статусов с датами, гонорары, охваты. Тогда и считать:

- надёжность = сроки + следование брифу по прошлым кампаниям;
- эффективность = охваты и вовлечённость на тенге гонорара;
- автоподбор под бриф = фильтр по нише и бюджету, отсортированный по этим двум.

## Какие API брать

| Задача | Что брать | Состояние |
|---|---|---|
| Статистика Instagram | **Instagram API with Instagram Login**, разрешение `instagram_business_basic` | код готов, ждёт одобрения Meta |
| Статистика TikTok | официального способа нет — только ручной ввод | не изменится в обозримом будущем |
| База, авторизация, файлы | Supabase (Postgres + Auth + Storage) | подключено |
| Хостинг | Vercel | готово к деплою |
| Уведомления агентству | Telegram Bot API | этап 2 |
| Уведомления клиентам | WhatsApp через Green API | этап 2, опыт уже есть на другом проекте |
| Почта (отчёты, приглашения) | Resend или SMTP Supabase | этап 2 |
| Платежи | не брать. Расчёты вне платформы, как сейчас | вне объёма |

Про платежи отдельно: соблазн «добавить оплату» появляется рано, но он тянет
за собой договоры, эквайринг, возвраты и налоговую отчётность. Пока агентство
работает по счетам, платформе там делать нечего.

## Чего сознательно НЕ делаем

- Мобильное приложение — только адаптивный веб.
- Публичные отзывы и звёзды — оценки видит только агентство.
- Автоматический матчинг «под ключ» — до этапа 4 это гадание.
- Парсинг Instagram в обход API — нарушает соглашение Meta и ставит под удар
  будущее одобрение приложения. Разбор в [INSTAGRAM.md](INSTAGRAM.md).
