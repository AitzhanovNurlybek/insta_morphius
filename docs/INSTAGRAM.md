# Статистика креаторов: откуда брать цифры

Проверено 2026-08-29. Ниже — что реально работает сегодня, а не что обещает документация.

## Короткий вывод

Mini MVP живёт на ручном вводе, и это правильное решение. Автоматический сбор
упирается не в код, а в доступ к данным: у всех трёх способов свои потолки.

| Способ | Что даёт | Потолок |
|---|---|---|
| Ручной ввод агентством | всё | время сотрудника; цифры устаревают |
| Парсер публичного профиля | просмотры/лайки/комменты последних постов | **подписчиков не отдаёт**, квота кредитов, серая зона по ToS |
| Meta OAuth (Instagram Graph) | подписчики, охваты, показы, демография | нужен App Review, 2–8 недель, creator должен быть Professional |

## Что показала проверка парсера

Прогон `get_instagram_profile` на публичном профиле (2026-08-29):

- **Отдаёт по каждому посту:** `views`, `likes`, `comments`, дату публикации,
  длительность, ссылку, обложку. Этого достаточно, чтобы посчитать
  **средние просмотры Reels** и **engagement по постам** — два из шести полей статистики.
- **Не отдаёт:** `followers` и `following` — приходят `null`. Число подписчиков
  автоматически не получить, оно остаётся ручным.
- **Стоимость:** один профиль на 3 поста списал 15 кредитов из 20 доступных.
  Второй запрос уже упёрся в `insufficient-credits`. На базу в 10–15 креаторов
  этого не хватит без платного тарифа.

Отсюда практика: парсер имеет смысл включать точечно — освежить цифры перед
конкретным предложением клиенту, а не как фоновую синхронизацию всей базы.

Готовые цифры кладутся в базу пачкой:

```bash
node --env-file=.env.local scripts/import-creators.mjs data/creators.json
```

Скрипт сам посчитает `avg_reels_views` и `engagement_rate` из массива `recent_posts`,
если их не передали явно. Источник при этом остаётся `data_source: manual` —
цифры из парсера не то же самое, что подтверждённые Instagram.

## Юридическая сторона (не пропускать)

Автоматический сбор данных с Instagram нарушает пользовательское соглашение Meta,
даже когда данные публичные. Для внутренней прикидки агентства риск невелик,
но **показывать бизнесу спарсенные цифры как «подтверждённые» нельзя** — это и
подстава под Meta, и обман клиента. Бейдж «✅ Подтверждено через Instagram»
в интерфейсе завязан на `data_source = 'api'` и загорается только после честного
OAuth-подключения. Так и оставить.

Промежуточный честный вариант, который используют агентства: креатор сам
присылает скриншот Insights, агентство вбивает цифру руками. Медленно, зато
не нарушает ничего и годится как доказательство перед клиентом.

## Что уже готово под Meta OAuth

Схема (`supabase/migrations/0001_init.sql`, таблица `creators`) содержит поля,
чтобы переключение с ручного ввода на API не потребовало миграции данных:

| Поле | Назначение |
|---|---|
| `instagram_connected` | креатор прошёл OAuth |
| `instagram_user_id` | id аккаунта в Graph API |
| `instagram_access_token` | токен (шифровать на уровне приложения) |
| `instagram_token_expires_at` | токен не вечный, нужен refresh фоновой задачей |
| `instagram_last_synced_at` | когда последний раз тянули метрики |
| `data_source` | `manual` / `api` — от него зависит бейдж доверия |
| `consent_data_processing`, `consent_at` | согласие на обработку данных |

Чекбокс согласия уже стоит в форме creator'а — понадобится и для App Review,
и для закона РК «О персональных данных и их защите».

## План подключения Meta (после Mini MVP)

Порядок важен: подавать заявку в Meta стоит, когда есть живой продукт с
пользователями — такие заявки одобряют охотнее концептов.

1. Завести Meta Developer аккаунт и черновик приложения **параллельно** с разработкой,
   не после. Business Verification компании занимает время само по себе.
2. Опубликовать Privacy Policy и Terms of Use — без них App Review не начнётся.
   Продукт простой, документы короткие; сделать заранее.
3. Набрать 2–3 месяца реальных кампаний в Mini MVP — это материал для заявки.
4. Запросить scopes: `instagram_basic`, `instagram_manage_insights`,
   `pages_show_list`, `pages_read_engagement`. По каждому описать сценарий использования.
5. Реализовать сам механизм: кнопка «Подключить Instagram» → Facebook OAuth →
   сохранение токена → фоновая задача обновления метрик → `data_source = 'api'`.

Ограничение, о котором нужно предупреждать креаторов заранее: работает только с
**Professional-аккаунтом** (Business/Creator), привязанным к странице Facebook.
Личный аккаунт переключается в профессиональный за пару минут и бесплатно, но
это отдельный шаг, на котором часть людей отвалится.

## TikTok

Официального способа получить статистику чужого аккаунта нет: Login Kit отдаёт
только базовый профиль, без охватов и аудитории. Программа TikTok Marketing Partner
закрытая. Вывод: TikTok-метрики остаются на ручном вводе, и это не временная
заглушка, а обозримое положение дел.
